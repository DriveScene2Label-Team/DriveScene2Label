RDS API에서 `AutomaticRestartTime=2026-11-25T06:24:52.942000+00:00`을 확인했다. 이번 재실행·중지로 이전 11월 25일 02:21 KST 예정이 갱신됐다. RDS는 최대 7일 뒤 자동 재시작하며 스토리지/백업 및 S3 저장/요청 비용은 남는다. [AWS RDS 중지 동작](https://docs.aws.amazon.com/AmazonRDS/latest/UserGuide/USER_StopInstance.html).

이번 재개 실험에서 EC2·ECS·EKS 컴퓨트를 새로 만들지 않았다. 첫 종료 때 확인한 미종료 EC2 0, EKS 0, ECS 실행/대기 task 0의 이력은 이전 operations 증거에 남아 있다. 이를 이번 시각의 계정 전체 재조사 결과로 표현하지 않는다.

Vercel URL 조회 도구는 임시 공유 링크를 만들 수 있다는 이유로 자동 승인 검토에서 거절됐다. 링크를 생성하지 않고 읽기 전용 프로젝트 메타데이터를 조회했다. 보호 설정을 우회하거나 배포를 재개하지 않았다.

## 데이터·로그·반영 범위

기존 dataset 21, job 13의 39프레임·1,308박스, recording 13과 모델/원본 볼륨을 보존한다. RRD·중간 후처리 cache가 S3에 새로 백업된 것은 아니다. Docker prune·볼륨 삭제·Windows 종료는 하지 않았다.

새 코드/이미지로 loopback 검색 전후 시험을 완료했으며 hybrid 기본값은 G2 전처리 reuse, C1 source prefetch, Q2 검색 전용 custom+MATERIALIZED, Q3 텍스트 LRU 256이다. Grounding/SAM 모델·정밀도·native thread 1은 유지한다. 현재 컨테이너는 중지되어 있고 다음 start에서 기본 설정이 적용된다.

원본 로그는 `.local/hybrid/measurements`, 최신 실행 묶음과 `report.md`는 `.local/hybrid/experiments/20261118T053317Z-resume/`에 있다. `rds-final-state.json`, `local-final-state.json`, `operations-quiesced.json`이 이번 종료 증거다. stdout의 UTF-8을 Windows cp949로 잘못 읽은 최종 상태 수집 실패도 sidecar로 남기고 UTF-8로 재수집했다. [Git 검토용 증거](evidence/optimization-resume-2026-11-18/README.md)는 비밀·원본 영상·모델·벡터 literal을 제외한다.

## 다시 켜기

1. PC·GPU·Docker를 준비하고 필요하면 AWS 로그인 세션을 갱신한다.
2. 저장소에서 `powershell -NoProfile -File scripts/hybrid.ps1 -Action start -SkipVercel`을 실행한다. 기존 RDS 시작, GPU/S3 인증, 유지보수 상태 해제를 처리한다. 이번 코드가 없는 이미지라면 start 전 backend·ai-server를 rebuild한다.
3. 공개 서비스가 필요할 때 Vercel을 Resume하고 `python scripts/hybrid/cloud.py vercel-sync`로 터널을 반영한다. 이번에는 공개 배포를 재개하지 않았다.
4. dataset 21·완료 job 13을 먼저 조회한다. 저장 결과를 확인하려고 라벨 작업을 다시 만들 필요는 없다.
5. 원복은 `SEARCH_EXACT_OPTIMIZATION_ENABLED=false`, `CLIP_TEXT_CACHE_SIZE=0`을 설정한 뒤 해당 컨테이너를 다시 생성한다. 새 실험은 새 measurement 폴더에서 시작한다.
