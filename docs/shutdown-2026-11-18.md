## 로컬 처리와 로그

RDS 중지 후 CPU 스레드 시험은 이미 복원된 로컬 파일을 읽는 별도 프로세스로 수행했다. 2026-11-18 03:36 KST 최종 확인에서 backend·AI·auth gateway·auth upstream이 모두 exited/running=false였다. TensorRT 빌드 중 사용자 요청으로 GPU 컨테이너를 중지했고 이후 GPU를 다시 켜지 않았다. 마지막 수집기는 STOP 후 종료 및 최종 수집 exit 0을 확인했다. S3/RDS 추가 실험은 실행하지 않았다. GPU 전력·컨테이너 상태는 검토용 operations 증거에 기록했다. Docker 볼륨 삭제·prune·데이터 초기화·Windows 전원 종료는 수행하지 않는다.

원본 측정은 `.local/hybrid/measurements`, 실험 비교와 실패 기록은 `.local/hybrid/experiments`에 있다. 각 실행의 새 폴더, 명령, 조건·입력·소스/이미지 해시, JSONL·stdout/stderr·자원 표본을 보존했다. Git에는 검토용 증거만 넣고 credential·원본 nuScenes·가중치는 넣지 않는다.

## 다시 켜는 순서

1. PC·eGPU·Docker를 준비하고 필요하면 기존 AWS 로그인 세션을 갱신한다.
2. 저장소 루트에서 `powershell -NoProfile -File scripts/hybrid.ps1 -Action start -SkipVercel`을 실행한다. 기존 RDS 시작, Docker/GPU·S3 인증, 인증된 쓰기 재개를 처리한다. 과거 EC2/ECS 배포 workflow는 실행하지 않는다.
3. 공개 서비스가 필요할 때 Vercel 프로젝트를 Resume하고 `python scripts/hybrid/cloud.py vercel-sync`로 새 터널 연결을 반영한다. 지속적인 Git 자동 배포를 원할 때만 `frontend/vercel.json`의 `git.deploymentEnabled`를 true로 복원한다.
4. 데이터셋 21과 완료 job 13을 재조회해 카메라·3D를 확인한다. 저장 결과를 확인하려고 새 라벨 작업을 만들 필요는 없다.
5. 새 실험은 새 measurement 폴더로 시작한다. STOP이 있는 이전 폴더에 다른 실행을 섞지 않는다.

이 종료 이후의 재시작을 실제로 검증한 기록은 아니다. 현재 중지 상태를 유지하며 다음 사용 시 위 절차로 재개한다.
