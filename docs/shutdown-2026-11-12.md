## 다음에 다시 켜는 순서

1. 서버 PC와 eGPU를 켜고 필요하면 AWS/Vercel의 기존 CLI 로그인을 갱신한다. 비밀번호·토큰을 README나 채팅에 붙여 넣지 않는다.
2. 저장소 루트에서 **아래 명령을 재개할 때만** 실행한다. 기존 RDS가 stopped면 시작하고 Docker/GPU·S3 인증·쓰기 재개·새 Cloudflare 터널을 준비한다. Vercel은 아직 공개하지 않는다.

   ```powershell
   powershell -NoProfile -File scripts/hybrid.ps1 -Action start -SkipVercel
   ```

3. Vercel의 `drivescene2label` 프로젝트에서 **Resume Service**를 실행한다. 또는 같은 프로젝트에 공식 `unpause_project` API를 사용한다. 사용하지 않는 과거 EC2/ECS/EKS start workflow를 실행하지 않는다.
4. 새 터널 주소로 현재 production의 연결을 갱신한다. 이 명령은 이미 검증한 production 소스를 다시 배포하며 작업 트리 소스 업로드 명령이 아니다.

   ```powershell
   python scripts/hybrid/cloud.py vercel-sync
   ```

5. 지속적으로 Git 자동 배포를 사용할 때 `frontend/vercel.json`의 `git.deploymentEnabled`를 `true`로 복원해 `release-version`에 commit/push한다. 변경하지 않으면 이후 Git push의 Vercel 배포는 계속 비활성화된다.
6. 공개 로그인 → 데이터셋 6 → 완료 작업 #12 재조회 → 카메라·3D를 확인한다. 결과를 확인하려고 새 라벨 생성 버튼을 누르지 않는다. 새 추론은 사용자가 원하는 씬에서 직접 실행한다.
7. 새 측정이 필요하면 `measurement.py begin`으로 새 세션을 만든 뒤 `watch`한다. 종료한 기존 세션에는 STOP 파일이 있으므로 새 시험과 섞지 않는다.

S3 데이터나 RDS를 새로 만드는 작업이 아니며, 이번 종료 후 재기동/복원까지 실제 검증한 기록은 아니다. [Vercel pause/unpause](https://vercel.com/docs/rest-api/projects/pause-a-project), [Git 자동 배포 스위치](https://vercel.com/docs/project-configuration/git-configuration#git.deploymentenabled).
