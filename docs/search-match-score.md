# 검색 일치도 (matchScore)

`GET /api/search/scenes`의 scene마다 원래 `score`(= 1 − 코사인 거리)와 함께 `matchScore`(정수 0..100, nullable)를 준다. 화면 카드는 "일치도 N점 · 단계"를 보여 주고, 툴팁에 원래 코사인 값과 "확률이 아님"을 적는다. %는 쓰지 않는다. 신뢰도·변별도·z-score 같은 필드는 두지 않는다. 단계는 같은 숫자를 읽기 쉽게 나눈 화면 표시이며 API 필드가 아니다.

## 왜 필요한가

CLIP의 텍스트–이미지 코사인 유사도는 잘 맞는 쌍도 0.25~0.3 정도에 머문다(modality gap). 0.258 같은 값은 사용자가 보기에 "26% 맞음"처럼 읽혀 신뢰를 떨어뜨린다. 그렇다고 결과 안에서 1위를 100점으로 맞추면 엉터리 검색어의 1위도 100점이 되므로 쓰지 않는다. 검색어와 무관한 고정 기준점으로 환산한다.

## 환산

aggregation별로 `lower`→0점, `upper`→100점, 그 사이는 선형, 밖은 clamp(`MatchScoreCalibration`).

- `lower` = 관련 없는 문장(동물·음식·설산 등 8개, 무작위 글자 포함)이 모든 scene에서 받는 점수의 90백분위
- `upper` = **짧은 검색어가 맞는 scene에서 받는 점수의 중앙값**. 검색어와 정답 scene은 `scripts/match_score_queries.mini.json`(nuScenes 설명에 그 내용이 있는 scene, 예: "night" → 밤 scene 3개)에 둔다. 2026-11-05까지는 scene 자신의 긴 설명 문장 점수를 썼는데, 사용자가 실제로 쓰는 짧은 검색어는 맞는 scene에서도 코사인이 낮아(중앙값 0.232 vs 0.259) 맞게 찾아도 중앙값 69점, "night"는 밤 scene 1~3위인데 47·44·32점으로 보였다.

설정의 `search.match-score.model-name`/`preprocess`와 응답 embedding이 다르면 기준점이 의미가 없으므로 `null`을 주고 화면은 원래 score를 보여 준다. 잘못된 기준점(upper ≤ lower)은 기동 시 실패한다. TOP_K_AVERAGE 기준점은 imageTopK=3에서 측정했다.

## 화면 단계

카드에서 숫자 옆에 단계를 함께 보여 준다(`matchLevel`, SceneCard.tsx): 80점 이상 **잘 맞음**, 50~79점 **관련 있음**, 50점 미만 **약함**. 단계도 확률이 아니며, 아래 표처럼 맞지 않는 scene도 80점을 넘을 수 있어 검색 화면 안내 문구에 이미지로 확인하라고 적는다.

## 측정값 (2026-11-05, nuScenes v1.0-mini 10 scene, ViT-L-14-quickgelu/openai, lr-square-crop-mean)

짧은 검색어 10개, 정답 쌍 17개, 오답 쌍 83개:

|aggregation|정답 쌍 중앙값 = upper|1위가 정답|오답 쌍 중앙값|80점 이상: 정답|80점 이상: 오답|
|---|---|---|---|---|---|
|TOP_K_AVERAGE|0.232|8/10|0.205|76%|31%|
|MAX|0.236|8/10|0.208|76%|33%|
|AVERAGE|0.182|6/10|0.165|88%|36%|

기준점을 바꾸면 숫자만 달라지고 순위와 구분력은 그대로다. TOP_K_AVERAGE에서 이전 기준(긴 설명, 0.259)은 80점 이상이 정답 29%·오답 10%, 새 기준은 정답 76%·오답 31%다. 정답을 높게 보이게 하면 오답 일부도 함께 올라간다. 정답과 오답을 더 벌리려면 검색 자체를 바꿔야 한다(VLM 자동 설명과 텍스트 비교, 더 강한 이미지-텍스트 모델 등, 미실험).

시험했으나 쓰지 않은 방법: 검색어 앞에 "a dashcam photo of"를 붙이면 맞는 scene 점수가 오르지만 모든 scene이 같이 올라(mini에 없는 "highway"도 82~95점) 구분력은 그대로였다(정답·오답 AUC 0.81 → 0.80). 결과 안 1위를 100점으로 맞추는 방식은 엉터리 검색어의 1위도 100점이 되어 처음부터 제외했다.

### 이전 측정 (2026-11-04, upper = scene 자신의 설명)

`python3 scripts/calibrate_match_score.py` 출력:

|aggregation|자기 설명 점수 (n=10)|다른 scene 설명 (n=90) 중앙값|관련 없는 문장 (n=80)|lower|upper|
|---|---|---|---|---|---|
|TOP_K_AVERAGE|중앙값 0.259, 0.208–0.285, 1위 5/10|0.230|중앙값 0.145, p90 0.173, 최대 0.194|0.173|0.259|
|MAX|중앙값 0.261, 0.211–0.287, 1위 5/10|0.233|중앙값 0.148, p90 0.177, 최대 0.209|0.177|0.261|
|AVERAGE|중앙값 0.205, 0.172–0.242, 1위 4/10|0.184|중앙값 0.104, p90 0.134, 최대 0.149|0.134|0.205|

lower는 지금도 이 표의 값을 쓴다. 아래 해석은 이전 기준 때의 것이다. 해석: 기본(TOP_K_AVERAGE)에서 "rainy night road → scene-1077"(0.258)은 99점, 다른 scene의 설명처럼 운전 장면 일반에 맞는 문장은 60점대, 관련 없는 문장은 대부분 0점이다. mini의 scene들이 모두 비슷한 도심 주행 장면이라 다른 scene 설명도 60점대가 나온다. 일치도는 "이 검색어가 이 장면과 사람 설명 수준으로 맞는가"의 척도이지 정답 확률이 아니다.

## 한계와 재보정

- 표본이 작다(짧은 검색어 정답 쌍 17개, 설명 정답 쌍 10개). 검색어 파일은 mini의 scene 설명에서 만들었으므로 다른 데이터셋은 그 데이터의 검색어 파일을 만들어 `--queries`로 넘긴다. trainval 등 데이터를 바꾸거나 CLIP 모델·전처리를 바꾸면 스크립트를 다시 실행해 `application.properties`와 이 표를 갱신한다.
- 설명 문장은 여러 요소를 나열한 형태라 짧은 사용자 검색어와 분포가 다를 수 있다.
